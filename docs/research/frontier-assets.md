# 第一批 Blender 原创怪物与塔

日期：2026-10-01。用户要求自行在 Blender 制作几个怪物、新塔及动作。本次交付五个低多边形美术样本，沿用现有“动作与实例”页供操作检查。

[打开模型与动作预览](https://w-sunjun-user.dev.clock-p.com/#/games/test-game?view=animation&asset=bone-crawler)。下拉框中的“原创”项为本批模型；左右实例可以分别播放、暂停、定位动作、销毁和重建。三个怪物可查看待机、行走、死亡，炮塔可播放开火，冰霜塔可查看待机和施法。

## 内容与制作方式

全部网格、PBR 材质、骨骼和动作关键帧均通过 Blender 5.1.2 Python 制作，没有使用第三方模型、贴图或现成动作。保留独立的 `.blend` 源文件，使用刚性分段蒙皮，适合本批低多边形造型；不将它描述为高精度雕刻或写实软组织动画。

## 文件和约定

- `assets-source/frontier/<模型名>.blend`：可编辑网格、材质、Rig、Actions，以及展示用灯光、相机和台座。选中 Rig 后在 Action Editor 切换动作。
- `public/assets/frontier/<模型名>.glb`：运行时资产，不含展示场景。
- `public/assets/frontier/SOURCE.md`：来源、动作时长、坐标、挂点和重建命令。
- `tools/blender/build_frontier.py`：制作、动作烘焙、导出、渲染、重新导入检查。
- `artifacts/frontier/`：各模型测量、Blender 渲染、总览图、实际 GLB 姿态检查及浏览器证据。

统一以米为单位，Blender 为 Z 向上、-Y 朝前，glTF / Three.js 为 Y 向上、+Z 朝前。`EnemyRoot` / `TowerRoot` 不随动作移动；怪物位移仍应由路线逻辑决定。脚底和尸体接地在制作阶段求解并烘焙到 Body 关键帧，不在运行时增加位置修补逻辑。

塔的 `TurretYaw` 包含可转动组件，底座保留在外部；`Muzzle` 是固定发射参考点。炮塔出膛约定为 0.4 秒，冰霜塔释放约定为 0.6 秒。动画事件不执行伤害；后续接战斗时仍由逻辑控制释放和命中。

## 复审修正

实际检查 Blender 渲染后，抬高了爬虫背甲，修正背甲埋入腹部造成的零碎色块；补齐小鬼膝肘关节，烘焙脚底接触；调整爬虫死亡时的抬头与收腿，让腹部落地。炮塔移除了挡住内膛的端盖，将后坐起点放在完整采样帧。巨怪使用暖色晶体和眼睛，与冰霜塔的冷色区分。

预览页复用现有实例和播放控制，仅增加明确的资源路径、语义动作映射和取景间距。克隆复用已有 `cloneSkeletonModel`，同一实例内的材质分组共享一套 skin，两个实例之间独立。没有向战斗的 `TowerData` / `EnemyData` 添加占位字段或新行为框架。

## 验证

- 每个 GLB 导出后重新导入 Blender，检查根节点和全部动作保留。
- `npm run build` 通过；`npm run test:runtime` 通过，包含旧战斗回归与新增实际 GLB 检查：30 fps 烘焙关键帧的变形顶点、地面接触、循环首尾、死亡末段定格、根节点不漂移，以及独立实例、暂停、复位和释放。
- `tools/browser/frontier-smoke.cjs` 通过：五个模型加载、独立动作、单次结束与定格、复位、销毁/重建、资源完全释放，以及 844×390 / 390×844 布局。截图已逐张检查；完整结果和录像位于 `artifacts/frontier/browser/`，页面错误和失败请求均为零。
- 首次开发服检查发现既有 `favicon.ico` 404，已通过浏览器网络记录定位，补入本地 SVG 图标后重跑通过。不是模型加载失败，也没有过滤掉错误来通过检查。
- 旧箭塔和 KayKit 骷髅的 `p1-5-6-smoke.cjs` 回归通过，包含不同速度、独立播放、死亡复位和重复卸载。一次运行在输出断言通过后以 143 退出；补充进程日志串行重跑，命令与 Chrome 均正常退出（0）。采用后一次完整运行作为通过证据，不据此归因前次退出或宣称长期稳定。

重建命令：

```bash
blender --background --factory-startup --threads 4 --python-exit-code 1 \
  --python tools/blender/build_frontier.py
npm run build
npm run test:runtime
```
