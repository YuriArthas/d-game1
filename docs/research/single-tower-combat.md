# 单箭塔战斗检查点

日期：2026-10-01。本记录保留单波检查点，已复审并提交为 `a338d13`。当前页面随后扩展为 [三波玩法](multi-wave-gameplay.md)；以下单波数据属于该提交的验证证据。此记录对应单塔战斗小步，不是 P2.4 独立交付完成声明。

[打开试玩页](https://w-sunjun-user.dev.clock-p.com/#/games/test-game?view=placement)（沿用现有登录入口）。本地使用 `npm run build`、`npm run serve`，打开 `http://localhost:4173/#/games/test-game?view=placement`。

## 可验证内容

1. 先在上排左起第 2 格和中间转弯附近各放一座塔，点击“开始波次”；战斗中可在出口前补第三座。
2. 骷髅沿路线行走，塔转向并拉弓；箭矢飞到目标后血条减少，两箭击杀一只。死亡动作播放完再释放模型。
3. 点击暂停，检查单位、弓弦和飞行中的箭都冻结；恢复后继续。
4. 重开恢复 100 金币、5 点生命、空地图和准备阶段。也可直接不建塔开波，检查漏怪与失败。
5. 点击空地可看射程圈。CPU/GPU 帧耗时保留在工具栏；展开“战斗详情”才采集目标、位置与资源详情。

当前样本：一张地图、一种塔、一种骷髅、一波 8 只敌人。敌人生命 10、速度 1.8 米/秒、击杀奖励 5；塔费用 30、射程 7 米、伤害 5、攻击间隔 1.2 秒、出箭延迟 0.5 秒、箭矢速度 14 米/秒。波次完成奖励 10，每只漏怪扣 1 点生命。

## 结构与规则复审

- 建造与实际战斗合并为 `BattleWorld`，原 `PlacementWorld` 移除。金币、生命、波次和结算只有一个所有者；格子 Map 兼作塔登记和占用索引。
- `TowerUnit` 自己索敌和推进攻击年龄；按剩余路线米数最短选目标，同距保留生成顺序。锁定即开始冷却；到出箭点再次检查原目标的存活和射程，失效就取消，冷却不返还。
- `ProjectileUnit` 只追踪原目标，以箭尖抵达胸口点作为命中；World 结算该次伤害并立即删除箭。原目标死亡或逃脱时箭失效，不会转向另一只或重复奖励。
- 路线、移动、受伤和死亡抽到实际玩法目录，原运行时实验页复用同一实现；实验用颜色参数保留在实验页，不进入怪物逻辑。
- `TowerData` 只增加已消费的 `range/damage/cooldown/windup/projectileSpeed`。未加入等级、攻击类型、升级表、资源 ID 注册体系、通用组件基类、对象池或空间索引。当前遍历活动敌人即可。
- 内容引用与数值在 Catalog 加载时验证；模型挂点与动作在资源加载时验证。没有默认配置、替代模型或吞错继续运行。建造仍先成功创建 View，再提交费用与占用。

每个 1/60 秒逻辑步先生成和移动敌人，处理漏怪，再处理已有箭矢，最后推进塔的攻击。到达出口优先于同一步命中；生命归零先判失败，不发本波奖励。新箭在下一逻辑步开始飞行。固定步最多补 0.25 秒，每帧只统一呈现一次；新生敌人的动画只获得自身已存在的时间。

塔的 Shoot 姿态直接采样逻辑攻击年龄；配置的 `windup` 映射到原动作 0.5 秒处。出箭点从加载时的真实动作姿态缓存，逻辑不读取上一渲染帧的挂点矩阵。动画完成事件仅用于死亡视图清理，不决定出箭、扣血或波次完成。

逻辑完成不等待尸体。失败时剩余活怪保留在最终位置，箭矢与待出箭目标清除；死亡动作仍可收尾，用户暂停可冻结收尾。重开与退出清除全部本局实例。模板、共享材质/几何与实例骨骼的释放归属分开。

复审修正了一个 UI 状态问题：移除 Canvas 上不必要的 `memo`，避免重开时塔已释放而格子颜色保留旧占用。状态面板自身按 100ms 更新，父面板只响应金币、生命、阶段或用户操作；不会每逻辑步重建 React 场景。默认诊断仅采摘要和建造信息，单位详情按需读取。

## 验证结果

`npm run build` 和 `npm run test:runtime` 通过。仍有现有单包体积提示；独立游戏入口和包拆分属于后续交付步骤。

逻辑与资产回归覆盖：

- 原建造事务、修改内容生效、固定步、按出生时间推进、骨骼变形和 GPU 查询回归。
- 索敌距离与同距顺序；出箭前死亡/离开射程、取消后保留冷却；箭矢追踪原目标和失效。
- 非致死命中、两箭击杀、两座塔同时射击同一目标只结算一次击杀、波次奖励不重复。
- 暂停蓄力、飞行与死亡收尾；带着塔/敌人/箭重开；所有实例只释放一次。
- 漏怪、失败优先于奖励；不同渲染分帧下得到一致战斗结果；多生成项、零间隔爆发生成；手动下一波基础状态转换。
- 实际箭塔 GLB：4 个朝向 × 3 种出箭延迟下，逻辑发射点与实际动作的箭尖位置误差小于 1e-6；拉弓姿态确实改变箭尖位置，逻辑发射点不受上一帧姿态影响；不同塔动作独立；飞行箭尖与命中坐标一致。

浏览器使用实际鼠标/触摸操作，成功运行的页面异常、console error 和失败请求均为 0：

## 提交前复审补充

再次复审复现并修正了两个表现边界：敌人在渲染帧最后一个逻辑步死亡时，死亡动作时间归零会跳过位置同步，导致模型停在上一帧位置；现在即使本帧没有死亡动画增量也同步最终位置。塔逻辑在累加 30 个 1/60 秒步后已判定出箭，但浮点误差可能让装填箭晚一帧隐藏；表现层现在使用与逻辑一致的出箭时间比较。两项回归均先确认失败，再修正通过，没有增加定义字段或额外状态。
