# P2.1 最小运行时与时间推进验证

日期：2026-10-01。本步只验证路线推进、暂停冻结和重新开始清理，不进入波次、经济、攻击、升级或 50 个怪物。

## 实现范围

- `RouteFollower` 只负责按 waypoint 和路线长度计算位置。
- `EnemyUnit` 保存单位身份、路线进度、速度和状态，并拥有自己的 `EnemyView`；它不把 Three.js 场景对象当作游戏状态。
- `EnemyView` 只同步位置和可见性，负责自身几何体和材质释放。
- `GameWorld` 拥有一条演示路线和三个单位，集中处理时间推进、暂停、重置和场景挂接。
- 测试入口为“塔防模型测试 → 运行时验证”。默认暂停；“开始”后单位沿折线路线前进；“暂停”冻结逻辑时间和单位 ticks；“重新开始”销毁旧视图并创建新一局。

## 浏览器验证

使用本地生产 `dist`、Chromium 1243 + SwiftShader，页面错误和 console error 均为 0。

- 初始局号为 1，三个单位均为 0 ticks。
- 开始后逻辑时间和三个单位的路线进度增长。
- 暂停后等待 300ms，报告中的逻辑时间、路线进度和 ticks 保持不变。
- 重新开始后局号递增为 2，三个单位的 ticks 全部回到 0，状态回到暂停。
- 已查看实际画面：三枚单位位于同一条可见折线路线上，测试控制区和报告区在当前桌面视口内。

复现构建：

```bash
npm run build
```

本步的截图保存在 `artifacts/p2-1-runtime.png`。无头 SwiftShader 只证明逻辑和画面挂接，不代表真实手机性能。

## 遗留边界

当前路线和单位是验证用最小样本，不是正式关卡或正式敌人对象；没有死亡、动画、波次、攻击、放置或性能压力测试。下一步应先讨论 P2.2 的数量与生命周期场景，再决定是否把该实验对象收敛为正式运行时结构。
